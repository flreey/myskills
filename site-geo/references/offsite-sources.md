# 站外 GEO：进入 AI 引用的来源

（原 site-offsite 的 GEO 模式，2026-11-25 并入 site-geo。投稿、复审、核验的记录一律走 bl：`~/Projects/backlink`，`bl guide`。）

AI 回答“推荐 / 有哪些 / 值不值得”这类问题时，主要依据第三方来源的一致说法，而不是产品自己的页面。
所以 GEO 模式的目标不是外链数量，而是：**在 AI 已经在看的那些来源里，出现准确的产品信息。**

1. **拿到 AI 实际引用的来源**：
   `python3 <site-geo>/scripts/cited_sources.py --root <项目> --own <自己的域名>`
   - 先读项目根目录的目标卡 `geo-goal.md` 和各 GEO 目录的 `gap/channels.md`：只做 Lever 含 `offsite` 的那些需求；目标卡把某个渠道列为不做时，不为它找来源。
   - 读各 GEO 目录的 `gap/runs*.jsonl`（site-idea 的缺口检查，含额外的运行集）和 `optimize/runs.jsonl`（site-geo 的持续优化），按域名汇总被引用次数、覆盖的任务数、来源类型、平台，以及同一回答里自己有没有被引用。一个站有多个 GEO 目录时，`cited_sources.py` 用 `--geo-dir`（可重复）逐个传入。
   - 产品缺席、覆盖任务多的排前面：这是 AI 已经在看、但还没有我们的地方。
   - 运行先跑过 site-idea / site-geo 的 `reads` 时，还会统计 AI 打开过但没引用的页面：`Opened` 是打开它的回答数，`Opened, we unseen` 是其中一个我方页面都没打开的回答数。后者高的榜单、清单文和目录，是 AI 找候选时在读、而我们没被找到的地方，优先进入。AI 打开过我方页面却没选我们时（选择阶段输了），先回 site-check 1G 修核验页，不靠站外。
   - 记录太少（少于 20 次回答）时说明“样本薄”，用 site-idea 或 site-geo 补跑问答，不凭印象列来源。
2. **按来源类型决定动作**（快筛和授权规则见 `bl guide` 的复审标准）：

| 类型 | 动作 |
|---|---|
| 榜单、清单文、alternatives 页 | 联系作者或编辑请求收录（要发信授权），附可核实的事实 |
| 目录、工具注册表、插件 / 应用商店、MCP 目录 | 提交或更新条目，描述和事实与官网一致 |
| 社区讨论（Reddit、论坛、Q&A） | 以真实身份回答相关问题，按社区规则披露关系；不批量发帖，不伪造推荐 |
| 文档、教程、开源示例 | 提交可运行的示例或集成说明（PR、文档贡献） |
| 竞品官网 | 不是站外目标：说明 AI 认为竞品页答得更好，交给 site-batch（批量页）或 site-geo（已有页）改站内 |
| 新闻、视频 | 只在有真实新闻点或素材时做 |

3. **事实一致**：素材包里的价格、限制、授权、能力，以项目的 `geo/facts.jsonl`（或产品事实来源）为准；各渠道说法不一致会同时伤害准确率和推荐。发现旧条目写错，优先改旧条目。
4. **记录**：要投稿的来源用 `bl add --url <入口> --evidence "GEO：被 AI 引用于 <任务>，引用域名 <域名>"` 进 bl 线索，复审、领单、核验照 `bl guide`；发信、社区帖这类 bl 授权外的，列给站长。
5. **回收**：不看 DR，看结果。第 28 天前后，用 site-idea 的问答方法（或 site-geo optimize 的固定问题）复测这些任务：产品有没有被提及、被引用、引用的是不是新进入的来源。只有 AI 回答里出现了，才算 GEO 模式的成果；条目公开但回答没变化，照实写。
