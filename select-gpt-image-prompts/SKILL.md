# GPT Image Prompt Selector

把用户的场景翻译成检索条件，从本地目录选出高相关候选，只保留有效的视觉机制，再改写成可直接用于图像模型的提示词。不要把整个目录加载进上下文。

## 工作流

1. 提取场景、主体、用途、风格、构图、画面文字、宽高比、参考图和禁用元素。信息足够时直接继续；只有缺失项会显著改变结果时才追问，最多一次问两个问题。
2. 将需求压缩成一条检索语句。保留具体名词和视觉机制，例如“咖啡 电商主图 极简摄影 悬浮构图”，不要只搜索“高级”“好看”。
3. 从当前 Skill 目录运行：

   ```bash
   python3 scripts/search_prompts.py "<检索语句>" --limit 3 --format json
   ```

   需要偏向特定用途时增加 `--category`，例如 `--category youtube-thumbnail`。用 `--list-categories` 查看可用分类。
4. 比较候选的用途、构图机制和可改写程度。选择一个主模板；仅当两个模板提供互补机制时才融合，避免堆叠互相冲突的风格。
5. 改写模板，而不是原样复制：
   - 替换示例主体、品牌、人物、地点、文案和 `{argument ...}` 占位符。
   - 保留真正有用的构图、镜头、层级、材质、光线和文字布局机制。
   - 将输出文字改成用户指定语言，并逐字保留必须出现的文案。
   - 明确宽高比、主体优先级、留白和禁止元素。
   - 用户未要求第三方品牌或受保护角色时，将模板里的相关名称替换成通用描述。
6. 交付一条主提示词，并简短说明参考了哪个候选及改了什么。若用户明确要求生成图片，使用图像生成工具执行最终提示词；若只要提示词，不要擅自生图。

## 检索判断

- 优先匹配用途和构图机制，其次匹配视觉风格，最后才匹配装饰性形容词。
- 把目录提示词视为参考模板，不把来源示例中的品牌、文字或人物设定误当成用户需求。
- 本地目录没有强匹配时，可组合最接近的结构并自行补全，但必须说明这是“基于候选结构新写”，不要伪称为原库条目。
- 用户要求最新、完整目录，或本地目录没有覆盖该场景时，说明本地索引只包含 GitHub README 公开的精选样本，再浏览上游图库补充，不要声称本地含有网站展示的全部提示词。
- 使用或改编具体条目时，在结果中保留条目标题和可用的来源链接。来源与许可说明见 [references/source-and-license.md](references/source-and-license.md)。

## 目录维护

本地索引不存在或用户明确要求刷新时，从当前 Skill 目录运行：

```bash
python3 scripts/sync_catalog.py
```

刷新后先查看脚本输出的条目数，再运行至少一次实际检索。不要在每次调用 Skill 时自动联网刷新。

## 输出要求

默认输出：

1. 选中的参考模板及选择理由。
2. 一条可直接使用的最终提示词。
3. 必要时列出参考图要求、宽高比或文字渲染注意事项。
4. 来源链接；没有精确来源时明确标注为综合改写。

不要输出长篇目录，不要同时给十几个候选，也不要把后台检索过程写成报告。
