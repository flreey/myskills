# 新站外链

用尽量少的时间，换到对新站真正有用的外链：让域名有排名能力，让新页面更快被发现，或者带来真实访客。
每条链接都要能回答两个问题：**谁会看到它？这里为什么允许推荐？**

## 基本立场

- **先定目标再选渠道。** 不同目标适合的渠道差别很大，见 [渠道分层](references/channels.md)。
- **按回报分配精力。** 投一个目录或发布平台通常要 5–15 分钟；一条博客评论几乎没有价值。不要因为“能发出去”就去投。
- **为读者推荐。** 不为操纵排名批量制造链接，参见 [Google 链接垃圾政策](https://developers.google.com/search/docs/essentials/spam-policies#link-spam)。
- **只算核验过的链接。** 没有独立看到公开链接的，不计入数量。

## 开始前（能推断就不问）

- **产品**：公开网址、一句话用途、目标读者、适合被推荐的页面。
- **目标**：加权重、加快收录、带引荐流量，可以多选并排序。没说明时，新站默认“加权重 + 加快收录”。
- **身份与授权**：
  - 身份：署名、联系邮箱、与产品的关系。
  - 动作：哪些渠道可以投；能不能注册账号、付费、接受强制回链徽章；能不能发邮件或社区帖子。
  - 没有明确授权的动作，只准备，不执行。
- **素材包**：项目里有 `backlink-kit.md` 就直接复用；没有就先建一份，见 [素材包](references/kit.md)。
- **台账**：已有台账时，先读状态摘要，处理到期的复查，再找新入口。

## 流程

### 1 定目标，选渠道层

| 层 | 渠道 | 默认 |
|---|---|---|
| T1 | 工具或 AI 目录、产品发布平台、alternatives 类站点 | 做：成本低，三个目标都沾边 |
| T2 | 专题资源页、清单文章、awesome 列表、竞品外链里能复制的位置 | 做：投入较大，加权重效果最好 |
| T3 | Reddit、Show HN、Indie Hackers、垂直社区 | 只为引荐流量做，严格按社区规则 |
| T4 | 博客评论、论坛签名、通用资料页或 web 2.0 | 不做，用户点名要求才做 |
| 付费 | Guest Post 挂牌、卖链站 | 不做；用户要求时只做评估，并说明政策风险 |

**`rel` 怎么看**：

- 目标包含加权重时，dofollow 加分；`nofollow`、`ugc`、`sponsored` 降一档，但不排除，因为它们仍然能帮助收录、带来流量。
- 目标只是引荐流量时，不看 `rel`。

### 2 找入口

找法和预算见 [找入口](references/prospecting.md)。按产出排序：

1. **竞品外链缺口**：选 3–5 个同类站（卖同一类东西，不只是读者相同），优先近期起量的新站，看它们的外链来自哪里，挑出可以复制的位置。项目里有 keyword-radar 的 `seo/radar/sites.md` 时，先从里面挑同类的。Semrush 订阅有效时，读各对照站的引荐域名报告（只看 Follow、按 AS 排序），合并后看重合。要大量候选时，改用下面的“海量挖掘模式”。
2. **已知类别**：按产品类别找当前还在收录的目录和发布平台。
3. **搜索指令**：用来找专题资源页、清单文章和 alternatives 页面。

### 3 快筛（每个候选 2–3 分钟）

先按域名和入口查台账，已经投过的先看状态，不为凑数重复投。然后看五项：

1. **相关**：目标读者会出现在这里，内容和产品用途对得上。
2. **允许**：当前入口接受这类推荐或自荐；禁止营销、禁止链接的地方直接排除。
3. **可行**：以实际表单为准，不以宣传文案为准。需要未授权的注册、付费、回链或身份信息的，记为受阻。
4. **有链接**：公开样本里有可点击的链接，记下 `rel`。只显示纯文本网址的不算外链。
5. **活着**：近期有新条目或编辑处理过。页脚年份、自动更新的日期不算。

按“目标匹配 × 可行性”排序，先投前面的。证据不足时标明不确定，可以少量试投，但不能说成已经验证过。

### 4 准备与提交

- **文案**：
  - 从素材包里取，按字段长度裁剪。
  - 写清具体用途和推荐理由，披露与产品的关系，品牌名自然出现，不堆关键词。
- **链接目标**：
  - 通用目录链首页；具体问题链对应的工具页；开发者集成链文档。
  - 不为外链专门新建页面。
- **执行范围**：
  - 只在授权范围内提交。同一任务里，批次授权持续有效，不每条都重新确认。
  - 只授权了一类渠道时，不自行扩展到别的渠道。
  - 遇到验证码、登录或站方条款，交给用户处理，不绕过。
- **提交后**：
  - 先判断结果再走下一步，状态不明时不重投。
  - `Awaiting Moderation`、表单被清空、按钮变灰，都不能单独证明提交完成。要检查是否还停在身份弹窗、字段报错或确认步骤。
- **工具**：浏览器按当前环境和用户指定的工具操作。不把含账号或私有信息的页面交给外部模型。
- **私密信息**：编辑密钥、私有编辑链接、凭据存在私有位置，不写进仓库、文案或截图。

### 5 核验与回收

- **公开后**：用独立访问核验，步骤见 [台账与核验](references/ledger-and-verification.md)。
- **待审的**：
  - 按站方说明的时间复查。
  - 站方没说明时，在第 3 天、第 7 天复查，之后每周一次，直到第 28 天。
  - 队列没有变化就不反复刷新。
- **第 28 天回收**，按渠道层汇总：
  - 每小时投入换到几条已公开外链、多少引荐会话（`site-measure`）；
  - 目标页的收录情况和排名变化（GSC，`site-plan` 的回看）；
  - 可选：DR 变化。
- 回收结果写进台账汇总，下一轮据此调整各层的优先级。
- 写了复查日期，不等于建好了定时任务。要提醒需要用户另外提出。

## 输出

- **存放位置**：
  - 关联项目时，台账和素材包放在 `<项目>/seo/backlinks/`；海量挖掘的清单是 `backlink-list.csv`，脚本输入和中间文件在 `ccgraph/`（中间文件加进 `.gitignore`）。
  - 账号、编辑链接这类私密信息放在项目约定的私有位置，不进版本控制。
- **每轮回复**：
  1. 本轮目标和渠道层；
  2. 新增公开的外链，附链接；
  3. 待审数量；
  4. 受阻项和解除条件；
  5. 耗时与积分；
  6. 下次复查日期。
  - 说明本轮是实际投稿还是只做了查询。
- **计数**：一个公开位置算一条，按层分开统计；“今天”按用户时区算。

## 新站批量模式

用户说“新站刚上线，尽快多找一些外链”时用这个模式：先一口气把候选和素材都备好，再按授权分批投。

0. **先问清两件事**（能从项目记录里推断的就不问）：
   - **放不放开邮件外联**：资源页、清单文、图书馆指南这类 T2 位置，大多要给作者或编辑写信。不放开的话，这些通过项全部只能进“需要你处理”。内容库类产品这一轮在 T1 上可能找不到可投的，整轮产出会是 0，所以要在开头就说明白。
   - **能不能注册账号**：Claude 不代为注册。要注册的站都列给用户。
1. **先定对照站，再挖**：选 3–6 个和产品同类的站，按 [找入口](references/prospecting.md) 的“选对照站”做，结果写进 `<项目>/seo/backlinks/competitors.md`。
   - **同类指卖同一类东西**，不只是读者相同。音效库就选音效站；做游戏美术的 Kenney、OpenGameArt 读者虽然相同，外链却大多来自“免费美术素材”页面，对音效产品没用（2026-11-08 sfxmint 实测踩过）。
   - `sites.md` 是 keyword-radar 按词收集的，里面的站不一定同类，只挑同类的用。
   - 不够时，用 Semrush 自然排名的“竞争对手”页，或 Similarweb 的相似站来补。新站在竞争对手页里的噪音很大（会混进 tiktok、youtube 这类大站），要人工挑。
   - 每个候选先看 1 页外链概览，引荐域名在几百到几千之间的最合适；按类型分组（例如“免费音效库”“游戏音效”“音效生成器”）。
2. **挖候选**：按 [找入口](references/prospecting.md) 的“引荐域名批量挖掘”来做：
   - 每个对照站读引荐域名报告第 1 页（只看 Follow、按 AS 排序），合并去重，数出每个域名链了几个对照站；
   - 先按规则排除，再用 AS 预筛（AS ≥ 30 基本等于 DR ≥ 30）；
   - 留下的逐行展开，看清具体页面，分出署名类和编辑类，只有编辑类进队列；
   - 再用第 2、3 类入口（已知类别、搜索指令）补足。外链差距报告只用来看重合，不当主路径。
   - 内容库类产品的外链大多是署名类，编辑类主要是资源页、清单文和图书馆或课程指南。
3. **一次性快筛**：
   - 每个候选 2–3 分钟，结果写进候选总表；
   - 排序时，被 2 个以上对照站同时链接的排最前；
   - DR 只给短名单查，其余用 AS；
   - 一轮快筛最多 50 个，剩下的留 `candidate`，下一轮从总表接着筛。
   - **按表计数**：按域名和页面分开数，写明读了哪些报告、哪几页、还剩多少没读。只读了第 1 页就写“抽样”，不写成全量。
4. **素材一次备齐**：
   - 素材包按线上能核实的事实补全，包括许可证、是否 AI 生成、免费额度的具体写法，再填好表单字段对照；
   - 每个通过快筛的候选，在台账里写明用素材包哪一段文案、链到哪个落地页。
5. **把要用户做的事集中交给用户，一次列清**：
   - 要注册账号的站；
   - 要付费、要放回链徽章的站；
   - 要发邮件或社区帖的站，如果第 0 步没放开；
   - 有验证码的站；
   - 要用户决定的事：例如利益冲突明显的公共 wiki 页、要满一定年龄或星数才收的 awesome 列表。
6. **分批投**：不需要上面这些条件的，在授权范围内按优先级连续投；其余的等用户处理完再投。

**这一轮交付什么**：
- 对照站表（入选理由、引荐域名数、AS）；
- 候选总表（快筛结论、所用文案）；
- 轮次文件（过程、计数、署名类的数量和例子）；
- 补全的素材包；
- “需要你处理”清单；
- 按层统计的数量。

用户没说只要列表时，不要只交一份域名列表；用户说“只要外链列表”，就以 `backlink-list.csv` 和一段漏斗计数为主，过程文件从简。

## 海量挖掘模式

用户要“大量外链”“几千几万个”“一份外链列表”，或 Semrush 抽样不够用时，用这个模式。做法、数据格式和口径见 [海量挖掘](references/cc-webgraph.md)，脚本在 `scripts/`。

1. **先说清量级**：候选池等于对照站引荐域名的并集，通常是几万个域名；能投的是几百到几千个。要几百万，只能换页面级的付费数据（DataForSEO、Ahrefs），先问用户。不造外链，只挖候选。
2. **下载要同意**：Common Crawl 域名级链接图约 11 GB，第一次用要用户同意并确认磁盘余量；已下载的同一版直接复用。
3. **对照站 20–50 个**，写进 `ccgraph/competitors.tsv`，按远近分组给权重（同类 3、相邻品类 1.5、同场景工具 1）；不放引荐域名几万个的大品牌。同行和姊妹品牌写进 `exclude.txt`。
4. **跑脚本**：`cc_extract.sh`（放后台，约 40 分钟）→ `cc_aggregate.py`（看“淹没”警告，删大站、补排除表后重跑）→ `cc_probe.py 3`（抓首页，约 6 分钟）→ `cc_build_list.py`。
5. **交付**：`backlink-list.csv`（自助投稿 → 要发信 → 待看 → 无入口，按 priority 排）加漏斗计数：对照站数、引荐域名、排除、候选池、≥2/≥3 个对照站、能打开、各类入口数，以及强/中档的数量。写明“域名级、首页自动探测，投前要人工确认”。
6. **接着走正常流程**：从“自助投稿”的强、中档开始快筛（第 3 步），在授权范围内投，要账号、付费、发信的集中列给用户。
7. **只要自助投稿入口时**：用 `cc_selfserve.py` 探测投稿页（竞品外链前几百个 + GitHub 免费目录列表），再逐个人工核对免费条件、注册、字段和 rel，见 [海量挖掘](references/cc-webgraph.md) 的“只要自助投稿入口”。

## 交接（不自动调用）

- 外链审计、有害链接排查：不在本 skill 范围，需要时在 Semrush 或 Bing Webmaster Tools 里查
- 新站哪些页面值得推：`keyword-radar`
- 引荐流量报表：`site-measure`
- 落地页验收：`site-check`

修改本技能时，用 [行为检查](references/behavior-checks.md) 做回归。
