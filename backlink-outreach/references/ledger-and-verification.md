# 台账与核验

**格式**：沿用项目里已有的格式，Markdown、CSV、JSON 都可以。没有台账时，在 `<项目>/seo/backlinks/ledger.md` 里建一张表。

## 字段

| 字段 | 说明 |
|---|---|
| ID、域名、入口 URL、层（T1–T4） | 定位和去重 |
| 目标、相关理由、接收规则 | 为什么值得投、为什么允许投 |
| 目标落地页、用的是素材包哪一段文案 | 防止重复投稿，也防止文案失真 |
| 状态、原因、更新时间 | 见下面的状态表 |
| 提交时间、回执或编号 | 用来判断有没有被接收、什么时候复查 |
| 公开 URL、目标 `href`、`rel` | 核验结果 |
| 首次公开确认时间、最近核验时间和方法 | 用于“今天多少”和存活复查 |
| 下次复查日期 | 方便续办 |

没查到的字段留空或写 `unknown`，不要猜。

**台账顶部放项目信息**：产品、目标及排序、授权范围、用户时区、基线（开始时已有的公开外链）。

**台账底部放回收汇总**：每轮各层的投入时间、公开条数、第 28 天的引荐会话。

## 状态

| 状态 | 含义和下一步 |
|---|---|
| `candidate` | 有线索，还没过快筛或还没提交 |
| `submitted` | 最终提交已完成，并有对应的接收回执。按复查日期去看 |
| `unknown` | 发起过提交，但没有可靠的接收证据。**先核查，不重投** |
| `live` | 独立访问能看到对应内容和可点击的目标链接，记下 `rel` |
| `no_link` | 内容已公开，但没有可点击的目标链接，不计入外链数 |
| `blocked` | 缺输入、权限、账号、费用，或技术上过不去。写明解除条件 |
| `closed` | 结束，原因写下面几种之一：排除（不相关或违反站方规则）、被拒（有明确的拒绝回执）、已删除（有充分证据）、失败（明确没有提交成功） |

- 没看到公开不等于被拒。
- 访问失败不等于已删除。
- 已经 `live` 的链接这次没访问成功时，保留上次的公开确认，并记“本次核验未知”。

## 公开核验

1. **确认最终提交**：身份确认、字段校验、验证码和最终按钮都处理完，回执确实属于这次投稿。隐藏的成功模板、前端占位都不算回执。
2. **独立访问**：用匿名 HTTP 或独立的浏览器页面，排除只有提交者能看到的内容。动态加载的评论或条目，不能只看静态 HTML。
3. **找到对应内容**：找到品牌名、条目或投稿正文。导航栏里同域名的其他链接不能拿来冒充。
4. **确认链接**：可点击，`href` 指向授权的落地页。
   - 站方的跳转链接记为跳转，需要时核实最终落点。
   - 纯文本网址不算。
   - 记下 `rel`，但不把它解释成排名承诺。
5. **留证据**：公开 URL、核验时间和方法。截图里不能露出私有编辑链接。

已经核验过、状态也没变的，不用换多个工具反复核验。

## 计数

- **默认口径**：一个公开位置算一条；用户要求按域名统计时，按域名去重。开始时说清楚用哪个口径。
- **分层统计**：T1–T4 分开统计，社区和评论不能拿来填 T1、T2 的目标。
- **今天**：按用户时区，统计当天首次公开确认的条数。没有精确发布时间的，称为“当天首次核验公开”。旧链接今天重新查到，仍按首次确认的日期算。
- **本目标新增**：相对于台账顶部的基线计算。
- **待审**：只算 `submitted`。`unknown` 和受阻的单独列出。
- 可以说“9 条投稿里 4 条已公开、5 条待审”，但不能把它叫作“审核通过率”。

## 常见误判

- **已出现 `Awaiting Moderation`，但姓名弹窗还在**：还没最终提交，继续完成身份步骤。
- **有接收回执，但公开页没有条目**：保持 `submitted`，按复查日期去看。
- **宣传说免注册，实际提交时跳登录页**：没有账号授权就记为 `blocked`。
- **姓名字段报错**：先看是不是格式问题，用授权过的写法。只有站方确实要求真实身份时才问用户，不编造姓名。
- **403 或脚本没加载**：记为核验未知，换一种支持的读取方式试一次。不能据此判定被拒。
- **平台不支持可点击链接**：记 `no_link` 或 `closed`（排除），不用 HTML 编码反复绕过。
